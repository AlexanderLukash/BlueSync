# BlueSync

Користувацький Python-сервіс для Linux/KDE, який автоматично дублює звук на підключені Bluetooth-аудіопристрої через PipeWire.

## Поведінка

- Підключайте навушники звичайним Bluetooth-інтерфейсом KDE.
- Один готовий Bluetooth-вихід → звук на ньому; два або більше → спільний вихід **BlueSync**.
- Після відключення одних навушників звук переводиться на решту. Після відключення всіх сервіс повертає попередній вихід, якщо він доступний, або інший наявний вихід.
- Сервіс перевіряє стан кожні 2 секунди й повторює спроби після перезапуску PipeWire. Під час перебудови виходу можлива коротка пауза.
- Після повторного підключення сервіс чекає стабілізації маршруту, призупиняє Bluetooth-вихід щонайменше на секунду й відновлює його. Відновлення може зайняти близько 6–10 секунд; це обхід проблеми мовчазного Bluetooth-транспорту, який потребує перевірки на конкретних навушниках.
- Автозапуск після входу користувача в систему. Підключення/спарювання пристроїв залишається відповідальністю KDE/BlueZ.

## Arch Linux / paru

Назва пакета — **bluesync-audio**. Пакет `bluesync` в AUR належить іншому проєкту.

До публікації в AUR пакет можна зібрати через `paru` з цього репозиторію:

```bash
git clone https://github.com/AlexanderLukash/BlueSync.git
cd BlueSync/packaging/aur
paru -Ui
systemctl --user enable --now bluesync.service
```

Пакет встановлює команду `bluesync-audio` та користувацький systemd-unit. Не запускає сервіс від root і не вмикає його автоматично для інших користувачів. Для налаштувань скопіюйте `/usr/share/bluesync/config.toml` у `~/.config/bluesync/config.toml`; якщо файла немає, використовуються стандартні значення. Діагностика: `bluesync-audio --status`.

При переході з `install.sh` після встановлення пакета зупиніть сервіс, перенесіть `~/.config/systemd/user/bluesync.service` у резервну копію за межами каталогу unit-файлів, виконайте `systemctl --user daemon-reload`, а потім `systemctl --user reenable --now bluesync.service`. Особисту конфігурацію збережіть.

У KDE ввімкніть «Показувати віртуальні пристрої» в налаштуваннях віджета гучності. BlueSync керує загальною гучністю, а повзунки фізичних навушників — кожною парою окремо.

## Вимоги та встановлення

Python 3.11+, PipeWire із `pipewire-pulse`, WirePlumber, BlueZ, `pactl`, systemd користувача. Сторонніх Python-бібліотек немає. `pactl` зазвичай постачається в `pulseaudio-utils` (Debian/Ubuntu) або `libpulse` (Arch); демон PulseAudio встановлювати замість PipeWire не потрібно.

```bash
./install.sh
```

Інсталятор копіює програму в `~/.local/share/bluesync`, конфігурацію в `${XDG_CONFIG_HOME:-~/.config}/bluesync/config.toml` і встановлює та запускає systemd-сервіс. Повторне встановлення зберігає конфігурацію.

```bash
systemctl --user status bluesync
journalctl --user -u bluesync -f
python3 -m bluesync --status
```

`--status` лише читає стан; із каталогу проєкту можна запустити сервіс вручну командою `python3 -m bluesync`. Блокування запобігає одночасному запуску двох екземплярів.

## Налаштування

Приклад — [config.toml](config.toml). `devices = []` включає **всі** Bluetooth-аудіопристрої, зокрема колонки. Щоб обмежитися двома конкретними навушниками, вкажіть їхні MAC-адреси. Вони доступні в налаштуваннях Bluetooth KDE або у властивості `api.bluez5.address` команди `pactl --format=json list sinks`.

Типово беруться лише виходи A2DP: сервіс не перемикає профілі та не втручається в мікрофони. Увімкнення мікрофона гарнітури може перевести її в HFP/HSP і тимчасово виключити зі спільного виходу. `a2dp_only = false` дозволяє й ці виходи, з можливою втратою якості.

`move_streams = true` переносить поточні й нові потоки програм на обраний вихід; ручний вибір іншого виходу для програми буде перевизначено на наступній перевірці. Значення `false` змінює лише типовий вихід.

Після редагування:

```bash
systemctl --user restart bluesync
```

## Архітектура й межі

KDE → BlueZ → WirePlumber/PipeWire → BlueSync. Сервіс спостерігає готові аудіовиходи через `pactl`, а не сам факт Bluetooth-з'єднання через D-Bus: з'єднаний пристрій ще не обов'язково має готовий аудіовихід. Нативний модуль PipeWire `module-combine-sink` дублює звук; `pactl` керує ним через сумісний PulseAudio API.

Документація: [Combine Sink](https://docs.pipewire.org/page_pulse_module_combine_sink.html), [Combine Stream](https://docs.pipewire.org/page_module_combine_stream.html).

Компенсація затримки ввімкнена, але різні навушники/кодеки можуть мати невраховану апаратну затримку: точна синхронність і відсутність затримки в іграх не гарантуються. Одночасні Bluetooth-потоки залежать від адаптера та радіоумов. Програми з прямим ALSA-виводом або вручну закріпленими нативними PipeWire-з'єднаннями можуть обійти типовий вихід; автоматичне перенесення охоплює потоки через `pipewire-pulse`.

## Перевірки

```bash
python3 -m unittest discover -s tests -v
```

Тести з імітацією аудіосервера охоплюють підключення, відключення, відновлення після перезапуску, нові потоки, захист від перенаправлення внутрішніх потоків комбінатора й перевірку конфігурації. Для апаратної перевірки підключіть дві пари, запустіть звук, перевірте появу BlueSync у KDE, потім по черзі відключіть пристрої. Окремо перевірте повторний вхід у систему.

## Вимкнення й видалення

```bash
systemctl --user disable --now bluesync.service
rm -f "${XDG_CONFIG_HOME:-$HOME/.config}/systemd/user/bluesync.service"
rm -rf "$HOME/.local/share/bluesync"
systemctl --user daemon-reload
```

Конфігурація зберігається. Під час штатної зупинки сервіс прибирає власний спільний вихід та відновлює доступний фізичний вихід. Після аварійного завершення наступний запуск підхоплює залишений модуль.
